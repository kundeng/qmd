# Branches and upstream PRs

Status: decided by the agent; the owner may reverse.

## Decision

Four stacked branches on `kundeng/qmd`, each the unit of one upstream PR, in dependency order:

| Branch | Spec | Upstream PR title |
|---|---|---|
| `live/01-writer-lock` | `docs/specs/01-writer-lock` | fix(index): one writer lock for update, embed, collection and cleanup |
| `live/02-daemon-proxy` | `docs/specs/02-daemon-proxy` | feat(mcp): share one daemon per index across stdio sessions |
| `live/03-live-indexing` | `docs/specs/03-live-indexing` | feat(index): keep the index current from file events |
| `live/04-project-collections` | `docs/specs/04-project-collections` | feat(init): docs and code collections for a project index |

`live/00-spec` carries `docs/design`, `docs/specs`, `docs/decisions` and `docs/history` and is not offered upstream; each code branch includes only the CHANGELOG lines and user docs upstream expects. Nothing is pushed to `tobi/qmd`; the owner decides on each PR.

## Why

Each PR must be reviewable on its own and leave upstream working at every merge point. The writer lock is useful alone (it fixes the unlocked `update`). The daemon is useful without the watcher (it removes the per-session servers). Live indexing needs the daemon. Project collections need live indexing to be worth having.
