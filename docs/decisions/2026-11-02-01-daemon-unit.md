# Daemon unit: one daemon per index file

Status: decided by the agent; the owner may reverse.

## Decision

A daemon serves exactly one index file. Its rendezvous key is `sha256(realpath(dbPath))` truncated to 16 hex characters, and its runtime files live in `~/.cache/qmd/run/<key>/` (`$XDG_CACHE_HOME/qmd/run/<key>/` when set): `daemon.pid`, `daemon.sock`, `daemon.log`, `index.json`.

## Why now

Sprint 02 needs a fixed answer before the first line of `src/daemon/paths.ts`.

## What was checked

- `getDefaultDbPath` (`src/store.ts:697`) resolves the global index to `~/.cache/qmd/index.sqlite`, a named index to `~/.cache/qmd/<name>.sqlite`, and `INDEX_PATH` overrides both.
- `findLocalConfigPath` (`src/collections.ts`) makes `qmd mcp` in a project with `.qmd/index.yml` open `.qmd/index.sqlite`, so one Claude session per project naturally lands on a per-project index.
- codegraph keys its daemon on the project root because its index is per project; qmd's index can be global, named or per project, and the file is what the writer lock must protect.
- A Unix socket path is limited to 104 bytes on macOS. `/Users/<user>/.cache/qmd/run/<16 hex>/daemon.sock` is 61 characters with a 7-character user name.
- `house-facts`: a socket or SQLite file inside a Dropbox tree corrupts across Macs, so runtime files never sit beside a project index.

## Options

| Option | Consequence | Reversal cost |
|---|---|---|
| One daemon per index file (chosen) | one writer per database, which is what SQLite needs; a project index gets its own daemon and its own model memory | low: the key function is one place |
| One daemon per machine serving every index | sessions for different projects would share a process; a crash takes down all; models shared | medium: session routing by db path inside the daemon |
| One daemon per project root (codegraph's unit) | the global index has no project root | not applicable |

## Consequences

Two projects open at once run two daemons and, while embedding, two copies of the embedding model (about 300 MB each, unloaded after 5 minutes idle). Measured in sprint 03 against the inventory-catalog project.
